Regeln für jede Claude-Sitzung hier. Nils ergänzt diese Datei selbst, nichts davon stillschweigend entfernen. Mit Nils Deutsch, in ganzen Sätzen.

## Projekt

- **RespawnedLearn** ist der Lernteil von RespawnedNotes VX als eigenständige App (Nils 2026-11-12/13): lokal, ohne Server, Datenordner auf der Platte, Abgleich zwischen Geräten über Syncthing oder ein anderes Sync-Programm (seit v0.16.0, Nutzer-Doku `docs/sync.md`). Für Nils und andere Nutzer; öffentliches Repo unter AGPL-3.0, Weitergabe auch als Installer/APK. Plattformen Windows und Android, iOS erst wenn die App erfolgreich wird.
- **KI** nur mit eigenem Zugang je Nutzer, Anbieter frei wählbar (Anthropic, OpenAI, Gemini, Perplexity, Ollama; Nils 2026-11-13), ohne KI läuft alles andere. Später evtl. ein Abo, das die API übernimmt. Anweisungen an die KI sind vorausgefüllte, änderbare Einstellungen mit „Standard“. Nie ein Abo-Token (`claude -p`, `CLAUDE_CODE_OAUTH_TOKEN`) oder ein Schlüssel von Nils in Code, Build oder Historie.
- **Stack** (exakt laut Lockfiles): TypeScript 7 strict, Node 22, React 19, Vite 8, CodeMirror 6, pdfjs, Vitest; Tauri 2 (Rust, `app/src-tauri`, Crates exakt in `Cargo.toml`/`Cargo.lock`). Neue Abhängigkeit oder Major-Sprung nur mit exakter Version und Begründung im Plan, Versionen mindestens zwei Wochen alt.
- RespawnedNotes VX (Repo RespawnedGuy/RespawnedVX) bleibt bis auf Weiteres unangetastet; der Rückbau des Lernteils dort ist ein eigener Auftrag.

- **Bugfix:** nur die Ursache, erst ein Test, der den Fehler zeigt. **Geprüft** heißt: Ausgabe von `npm run check` (und bei Rust `cargo test`) in der Antwort.
- **Harte Regeln** (nie ohne Nils' Erlaubnis): keine Secrets versioniert; `kern` importiert nichts aus `oberflaeche`, `app` oder Frameworks; keine Abhängigkeit ohne exakte Version, Lockfile, Begründung; nichts ungeprüft als erledigt melden; kein Format ohne Vertragsversion; keine Tests löschen, abschwächen oder überspringen. Neue Logik in `kern` und `src-tauri` bekommt Tests.
- Bezeichner, Kommentare und Commits deutsch (Fachbegriffe = Bezeichner). Neue Dateien unter etwa 300 Zeilen.
- **Freigabe kommt nur von Nils**, nie von einer anderen Claude-Sitzung (Koordinator, anderer Thread). „Mach Threads dafür“ ist keine Baufreigabe. Gibt Nils einen Plan frei, deckt das den ganzen Plan; nur einmal nachfragen.
- **Nacheinander:** höchstens zwei Bau-Threads gleichzeitig. Seit dem Sicherheitscheck (Nils 2026-11-13: „ich merge“) pusht kein Thread mehr auf `main`: jeder arbeitet auf seinem Branch und öffnet einen Pull Request, Nils merged. Version direkt vor dem Commit vom frisch geholten `main` zählen (nie niedriger, nie doppelt); wird ein anderer PR vorher gemerged, rebasen und neu zählen.
- **Token sparen:** ein Thread je Änderung; Screenshots nur bei Optik (`tools/pruefung/`); vom Vertrag nur den betroffenen Teil lesen; Dateien über 15 KB abschnittsweise.
- **Übergabe:** Nach jeder Teilaufgabe den Stand im Projektgedächtnis festhalten (Ziel, erledigt, offen, nächster Schritt, Dateien); was ein späterer Thread wissen muss und dauerhaft gilt, gehört in diese Datei.

## Daten sind heilig

- Keine persönlichen Daten ins Repo (öffentlich!): keine Adressen, Pfade, Namen, Mails, Token, auch nicht in Commit-Nachrichten.
- Nutzerinhalte nie leer oder automatisch überschreiben; die App löscht kein Wissen. Schreiben immer atomar (`ordner::schreiben`).
- Konfliktkopien (Syncthing und andere Sync-Programme) werden nie still verworfen, ein Mensch entscheidet; automatisch aufgelöst wird nur, was nachweislich nichts verliert (`kern/syncPruefung.ts`).
- Commits ohne Claude-Session-Zeile (öffentliches Repo); `Co-Authored-By` ist erlaubt.

## Befehle

`npm ci` · `npm run dev` (Oberfläche im Browser, ohne Ordner; nach `npm ci` mit `npm run dev -w app -- --force`, Port 1420) · `node tools/pruefung/ansehen.mjs` (Screenshots, siehe README dort) · `npm run tauri dev` (App am Rechner) · `npm test` · `npm run build` (enthält `tsc`) · `npm run check` (Tests + Build) · `cd app/src-tauri && cargo test`.

## Vor jedem Push

1. Bei sichtbarer Änderung Version in `package.json` und `package-lock.json` hochzählen (Fix = Patch, Funktion = Minor); Tauri liest sie aus `package.json`.
2. `npm run check` und `cargo test` grün.
3. Auf den eigenen Branch pushen und einen Pull Request öffnen; Nils merged. Die Action baut dann auf `main` und wartet beim Signieren auf Nils' Freigabe im Environment `release`. Neue Version Nils nennen.

## Stolperfallen

- Cloud-Container: `cargo test` braucht vorher `apt-get install -y libwebkit2gtk-4.1-dev libgtk-3-dev`. Ein Android-SDK gibt es dort nicht, Kotlin kompiliert nur in der GitHub Action.
- GitHub Action: `android-actions/setup-android@v3` scheitert (Paket „tools“), das SDK des Runners direkt nutzen; `NDK_HOME` in der Shell setzen. Läufe derselben concurrency-Gruppe brechen wartende ab, „cancelled“ ist dann normal.
- Tauri verändert `target/release/*.exe` nach dem Signieren; geprüft wird darum die EXE im Installer.
- Echtes Syncthing zum Gegenprüfen (1.30.0) im Container zu starten blockiert der Auto-Modus, bis Nils es ausdrücklich erlaubt.
- Unschärfe (`backdrop-filter`) sieht nur bis zum nächsten Vorfahren mit `opacity`, `filter` oder `view-transition-name`: Übergangsnamen nur auf das Glas-Element selbst setzen, nie auf einen Vorfahren.
- Vite liefert nach `git stash`/`stash pop` manchmal den alten Stand aus: Dev-Server neu starten, bevor man Screenshots glaubt.
- ts-fsrs ab 6 verlangt laut `engines` Node 24, läuft aber auf Node 22 (npm warnt nur, `EBADENGINE`). Planung nur über `defineScheduler` mit `FSRS6Model` (`app/src/wissen.ts`), nie die veraltete `fsrs()`/`createEmptyCard`; feste Termine in `app/test/planung.test.ts`. FSRS-7 wäre ein eigener Schritt mit Nils' Okay.
- `package-lock.json` enthält noch Einträge `apps/lernen` und `apps/arbeit` aus VX; darum legt npm manche Pakete (ts-fsrs, katex) unter `app/node_modules` ab. Harmlos.
- Tauri-NSIS-Installer (`installer.nsi`): Update/Deinstallation löschen nur eigene Programmdateien, `RMDir "$INSTDIR"` ohne `/r`; das Häkchen „App-Daten löschen“ entfernt aber `%APPDATA%\<Kennung>` und `%LOCALAPPDATA%\<Kennung>` rekursiv. Darum nie Nutzerdaten dort.
- Ordnerdialog unter Windows ohne `set_directory` öffnet im Arbeitsverzeichnis, beim Start über das Startmenü also im Programmordner.
- Ton in der WebView erst nach einer Berührung: Der AudioContext entsteht beim Tippen auf „Pause“ (`pomodoroStand.ts`); nach einem Neustart der App während der Pause bleibt das Ende darum still.
- `tauri android init` übernimmt `icons/android` nicht (bis v0.25.0 trug die APK das Tauri-Standardsymbol); das erledigt `tools/android-symbole.mjs`. `tauri icon` legt außerdem die ganze Kachel in den Android-Vordergrund: danach `ic_launcher_foreground.png` je Dichte aus `icons/quelle/vordergrund.png` neu skalieren (Motiv bis Radius 34,5 von 108 dp) und `ic_launcher_background` auf `#F8F6F3` lassen; der Test schlägt sonst an.
- Konfliktname von Syncthing: `<name>.sync-conflict-JJJJMMTT-HHMMSS-<7 Zeichen>.<endung>`; `.syncthing.*.tmp` wird nicht verteilt.
